## 一轮独立模型提示评估

对16条样本分别生成筛选结果，再在全新上下文中撰写两版简报。执行者没有读取标准答案；这不是正式部署模型的在线 A/B，也没有足够次数作统计等效结论。

- 两版均覆盖16/16候选 ID，选中集合相同，报告覆盖12/12项。
- 与预设二元判断均为15/16一致：两版都将已被更正的旧会议排除，并在新会议保留取消与改期信息。预设选择保留旧通知再合并，故没有事后改答案称为满分。
- 人工复核及事后事实清单检查：12项关键事项的事实、日期和要求均保留，包括长正文末尾的作业截止、PDF与代码、88元账单、86/100评分、未知日期及取消场次。未观察到声称已发送、支付、创建日程或提醒。
- 前8个有期限事项顺序一致；只有两个无明确截止日期的事项交换次序，12项有65/66成对排序关系相同。课程阅读的可选 information_type 也从 assignment 变为 material，不能声称输出完全不变。
- 文风与输出长度发生变化，真实输入/输出/推理费用仍需在目标模型上测量。

## 单次全局候选（仅实验）

另用同一16条完整输入制作一次返回 decisions、body、source_item_ids 与 reports 的全局请求。输入包估算3,321，低于去重两阶段的7,193；一次模型试验生成16条decision及12份报告，通过现有筛选/正文业务校验，保留了关键事实与线程更正。该请求不在正式运行代码中。

这只覆盖首次生成的小样本，未验证目标部署模型、上下文/输出上限、规则变更、已有线程增量更新及中断恢复。它也多次在正文复述了筛选规则，仍有写作质量提升空间。不能由此次结果推定全局方案普遍更好，本次发布选择保留现有流程的去重版。

## 后续架构选项（仅建议，未实施）

“一个 Agent”不等于“一次模型请求”。当前 stella-spawn 是全新空对话，不复制父历史；单个持久 Agent 多轮处理可能反复携带越来越长的历史。缓存命中可能降低费用，但不会让重复输入自动消失。

小规模可试一次全局请求同时给出 decisions 与 reports，使完整原文只输入一次，并改善跨来源关联。程序仍需验证全部候选覆盖、被选条目、线程赢家、排序和来源引用；一次失败的重试成本更大，结构化输出也可能超限。

大规模优先保留分批和可恢复检查点。若需要跨批关联，可增加只读取带来源ID事实卡的轻量总编，对冲突按需提供对应原文。额外总编不是天然省token；只有事实卡足够紧凑且质量收益值得时才采用，不再把全部原文重发一遍。

对比现有去重两阶段、单次全局、分批加总编三组，使用同一目标模型、规则和数据进行多次配对评估。记录完整输入、输出、推理、缓存token、费用、延迟与失败重试，评价关键事项召回、事实准确、截止日期、线程合并、跨源关联及整体排序。根据实际序列化输入和预留输出预算选择路径，不以固定条数判断。
