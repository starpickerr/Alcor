# Agent 协作

在侧栏打开“Agent 协作”，新建任务并选择参与者。Stella、Codex CLI、Claude Code 和 Cursor CLI 均可参加，任务可仅使用外部 Agent。“管理接入”负责初始化、启停与显式探测；探测仅检查安装状态，不证明账号已登录。

左栏切换任务，中栏保存正式消息，右栏提供流程、过程和 Agents 三个视图。编辑流程时选择每步执行者与前置步骤；无依赖步骤最多三路并行，依赖成功后执行后续步骤。可由任一参与者输出 `{"steps":[{"stepId":"plan","title":"目标","participantId":"任务内参与者 ID","dependsOn":[]}]}`，再明确采用流程提案；采用前仍校验归属、循环与执行历史。

公共消息对任务参与者可见，定向消息使用稳定参与者 ID。通过接收者菜单发送“人设：…”或在 Agents 面板编辑，修改的是同一份任务内设定。Agents 面板还可选择负责人和加入参与者；无定向对象的“发送并执行”交给当前负责人。模型可使用接入默认或显式 ID，CLI/模型服务负责验证 ID 是否实际可用，错误会保存在执行记录中。人设和模型修改只影响下一次执行，过程面板保留本次实际使用的配置快照。

过程输出持续保存至 Core 执行事件，页面关闭不停止调度。只有接入明确提供的正式最终消息才进入中栏；普通文本和工具输出留在过程面板。命令成功退出不证明有正式答复。每步最多三次尝试，每次默认 180 秒，任务调度最多 30 分钟；CLI 输出超过 8 MiB 会停止并标记结果未知。取消、失败或结果未知后可显式重试，保留旧尝试；重试前应确认前次是否已经产生外部副作用。Core 重启后无法恢复的执行显示结果未知，不自动重放。

任务参与者只收到任务目标、当前步骤与允许共享的正式消息；不会加载其他 Agent 的私有聊天或记忆。工作区、操作权限、撤销和进程隔离仍由 Core 执行。旧 provider 配置和历史委托保持可读。

当前以新一轮调用共享上下文，不提供 CLI 会话续接；Codex App Server 与 Cursor ACP 的协议执行仍不支持。测试使用合成 CLI 和模型；真实账号的认证、网络与模型可用性须在选定环境验证。
