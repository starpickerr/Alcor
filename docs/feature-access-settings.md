# 功能内的访问设置

安全中心不再提供独立的资源授权页面或全局管理 API。管理入口与功能归属一致：

| 功能 | 管理位置 |
| --- | --- |
| 数据来源、邮箱与 eLearning 账号、数据访问范围 | 数据管理 → 信息源；尚无数据源时也可配置第一个账号 |
| 任务执行模式及任务的数据／连接访问 | 任务管理 → 当前任务的独立权限 |
| 插件／MCP 访问与连接范围 | 能力管理 → 对应提供者的配置 |
| 历史非 MCP 用户级连接限制 | 能力管理 → 连接访问设置（仅展示已有记录） |
| 对话模式及该对话的历史连接限制 | 对话权限设置 |

安全中心继续负责默认模板、安全活动、凭据状态与其他安全概览。任务区只提供进入任务管理的入口。旧 `?tab=connections` 书签转到信息源，不再显示独立授权管理。

## 原地接管既有授权

这次迁移改变管理归属，不复制、重签发或清空授权。现有 `resource_grants`、`resource_restrictions` 和历史 MCP grants 仍使用原数据库；ID、主体、操作范围、用途、revision、父授权、有效期和撤销状态不变。读取新的管理视图不会恢复已撤销授权，也不会把已有范围转换为无限范围。

首次进入时保留旧配置中的功能入口；业务设置在读取或编辑前调用既有迁移核验，失败时拒绝变更，避免旧限制尚未迁移就被绕过。

各业务 API 先验证真实的数据源、任务、插件或连接，再过滤其可管理记录。任务和对话按 Agent 与主体标识绑定；插件按消费方绑定。跨功能的 grant ID、资源和过期 revision 会被拒绝。账号归属、对话／任务运行策略及实际资源检查继续由既有 Security Service、Gateway 与 Data Service 执行。

已移除的连接／插件若仍有关联授权，在能力管理保留仅用于查看和撤销的入口；不支持借此新增或恢复授权。旧课程已不再被选中时，原授权仍可查看、收紧和撤销。过期范围原样回传不会被当作重新签发期限。

用户级非 MCP 连接限制保留原键，例如 `browser`，不会转换为 `mcp:browser`。任务／对话的历史连接限制仍属于各自原主体。连接范围中的旧空列表按原语义显示为“所有操作”；新保存必须明确选择操作或关闭访问。

## API 清理

删除 `/api/security/resources`、`/api/security/connections`、`/api/security/mcp-access` 及其旧处理器和客户端方法。业务内设置使用 `/api/data/access`、`/api/tasks/access`、`/api/sessions/access`、`/api/capabilities/access`；它们共享同一个管理实现和既有存储，不构成另一套权限判断。

验证使用临时用户与授权数据，覆盖作用域隔离、存量授权有效性、撤销、过期、父子关系、版本冲突、首次账号配置及各业务页面。未对真实用户数据库执行破坏性迁移或清理。
