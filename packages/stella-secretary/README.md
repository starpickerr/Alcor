# @stella/secretary

将官方 DSH 桌面客户端扩展为可切换的 Stella 私人秘书。当前组合支持官方 DSH `0.2.2-alpha.3` 与 `0.2.2-rc.1`；macOS Apple Silicon 的发布安装包为本轮桌面验证目标。其他版本和平台须单独验收。

## 用户安装

1. 安装受支持的官方 DSH 客户端，打开原生“插件 / Plugins”页面。
2. 通过原生插件管理器安装 Stella 的 `.tgz` 安装包。完成后退出并重新打开 DSH；插件的安装、启用、停用及卸载按重启生效使用。
3. 使用窗口顶部的切换按钮选择 **Stella** 或 **DeepSeek Harness**。模式切换即时生效，不需要重启，也不会另开浏览器或网页服务。分别保存窗口的模式和上次位置。

安装使用 DSH 的宿主、模型、会话、工作区、插件管理和桌面承载，不修改官方 App 文件。包内的五组界面扩展由原生 Bundle 在当前 Profile 中装配，保留官方模块身份以兼容现有插件；它们是明确标注来源和 MIT 许可的 Stella 维护衍生模块，不是官方发行包。卸载后重新打开 DSH，恢复原生界面；会话、配置和业务记录保留。

## 使用与数据

Stella 提供 Agent 协作、事务、日程、简报、账单与定时的应用入口。事务和日程可展开当前页面内的原生会话；账号和设置复用原生窗口，自动化复用 DSH 调度器。秘书会话显式使用 `stella` Preset，切回 DSH 沿用用户原来的默认 Agent、模型与会话。模式切换本身不调用模型。

官方 Desktop 使用自带的 Python 运行环境执行随包领域服务，无需用户另装 Python。Web 开发预览仍需要 Python 3.9+。业务 SQLite 位于当前 Profile 的 `stella/business/`，与原生 Host 工具和页面共用；不会自动导入历史 Stella 私人业务库。功能差异以源码仓库 `product/feature-parity.md` 为准，不把安装闭环当作所有原六项功能已经全部迁完。

Apple 日历与提醒事项由可选原生插件 `@stella/apple-sync` 管理：选择来源及分类／清单，点击同步保存并开启双向同步；授权由用户操作发起。身份偏好、MCP 来源和 eLearning 连接仍需用户在原生设置中显式配置，沿用 DSH 的凭据和模型设施。停用时停止本包协作、暂停所属自动化；重新启用不自动恢复已暂停的定时任务。

业务采用已选择的本机可信应用模式，同账号的其他插件和执行工具可能访问本机数据，不承诺系统级隔离。秘书 Preset 的工具筛选与执行检查、MCP 撤销和委托限制继续有效。协作和自动化发送用户填写或保存的任务；生成简报会将所选来源内容交给用户配置的模型。打开页面或切换模式不会自动发送私人业务数据。

## 开发与兼容

完整来源与界面扩展摘要见 `vendor/NATIVE-UI-PROVENANCE.json`，许可随衍生模块保留。开发安装、构建、官方 Desktop 验证和已知限制见源码仓库 `product/README.md`、`product/compatibility.md`。官方客户端的 UI 根节点不支持本组合的无重启热替换；不将热安装／热卸载作为已支持能力。
