# Apple 同步

独立 DSH 原生插件 `@stella/apple-sync@0.1.15`，与 `@stella/secretary@0.1.51` 配合使用。支持官方 DSH 0.2.2-alpha.3 / 0.2.2-rc.1、macOS 和公开 EventKit。安装、查看状态不请求 Apple 权限；首次点击同步才由独立的 Stella Apple Sync.app 请求完整访问，不修改官方 DSH 的签名。

配置页的“同步”连接所有可见日历／提醒事项清单，“暂停同步”保留连接关系和本地内容。分类／清单与 Apple 一一对应，事务清单在日程页聚合显示为“事务”。每条日程和事务必须有归属；新建默认采用 Apple 的默认可写日历／清单，新建分类可选择 Apple 账户。同名跨账户保留不同身份，界面显示账户。新资料库不预建额外分类；已有分类、记录 ID 和专有字段均保留，无分类旧记录迁入有效归属。

已连接的删除操作先持久排队，Apple 确认后才删除本地。失败保留数据，可重试／取消；若待删项目被 Apple 修改，删除暂停并显示冲突。分类内容权限与分类属性／删除权限分别遵循 `allowsContentModifications` / `isImmutable`。来源 ID 变化优先重新关联，账户不在线、身份不明确或有本地未同步更改时保留数据并提供处理入口。已知账户在线且无新身份候选、分类内记录均已同步且未改动，跨一分钟独立确认来源缺失后才传播 Apple 分类删除；旧身份信息不足时需要明确确认。项目删除同样经过独立查询和连续缺失核对。

日程记录原生系列、实例和例外的关联及完整重复规则快照；本次／本次及将来编辑交由 EventKit 执行。跳过本次会删除对应原生实例。重复事务完成交由 Apple 推进，保留完成历史，不能提前完成未来实例；未返回明确下一实例时保持待核对，不自行推算或重复创建。

| 字段／能力 | 处理 |
| --- | --- |
| 日程标题、备注、时间、全天、地点、时区／浮动时间、公开 URL、绝对／相对提醒 | 双向；按来源权限写入 |
| 单条原生重复规则（含次数、间隔、第几周等） | 完整读取保留；实例／将来范围由 EventKit 执行；简单规则可编辑 |
| 提醒事项标题、备注、日期／时间、时区、优先级、完成状态、URL、支持的重复／提醒 | 双向；复杂原生规则或位置／多重提醒完整保留为只读并显示“部分同步” |
| 受邀人及参与状态 | 公开 EventKit 读取、只读展示；不模拟邀请写入 |
| 多条重复规则、位置提醒 | 完整原生快照保留，受限字段在 Apple 中编辑 |
| Stella 标签、旗标、层级、依赖、私有提醒渠道 | 本地保留；不宣称同步为 Apple 私有字段 |
| Apple 私有紧急闹钟、附件、智能清单等未开放能力 | 不模拟；不覆盖原生项目中的这些内容 |

公开 URL 不再存内部标记。新写入使用私有持久回执；中断后没有明确回执的创建进入待核对，防止盲目重复写入，旧 URL 标记仅兼容读取。

默认同步最近一年到未来两年。查看其他日期会按需增量加载，每次不超过 370 天，保存范围与时间；读取失败不推进覆盖范围，暂停时显示本地缓存。原生扫描按不超过三年分段以遵守 EventKit 的四年查询限制；每来源超过 20,000 实例视为读取失败，不把截断结果当成删除依据。提醒事项读取全部现有记录（含已完成项目）。持续同步需保持 DSH 运行。

同步映射位于 `<profile>/stella/apple-sync/`，领域数据仍由 Stella 业务服务拥有；通过内部 `stellaOrganizer.applePeer` 调用，不直接写业务库。首次升级以 SQLite backup 复制旧映射，保留原文件。内部确认／权限写入方法不进入模型调用目录。暂停、停用、卸载均保留本地数据及映射。

验证：`apple-contracts.py`、`apple-native-fields.py`、`business-recovery.py` 和产品回归；`unified-calendar-check.py` / `task-cards-check.py` 使用官方 Desktop、临时 Profile 与合成 EventKit。真实账户授权和跨设备收敛不属于合成测试证据。

旧版曾允许“删除分类、保留记录”。若升级发现分类映射失效但记录仍存在，会恢复原有效归属并显示待确认，保护已有内容；确认保留可继续同步，明确删除则使用新的分类管理删除流程。不会把这种旧状态自动视为删除 Apple 内容的授权。

0.1.15：编辑单次重复实例并更换日历时，以原日历查找实例、向所选可写日历保存；沿用本次／将来范围和权限检查。
