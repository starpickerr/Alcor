# Alcor

将官方 DSH 桌面客户端扩展为可切换的 Alcor 私人秘书。秘书 0.1.106 的精确宿主范围为 `0.2.2-alpha.3 || 0.2.2-rc.1 || 0.2.2-rc.2 || 0.2.2-rc.3`。本轮事务入口修复已在官方 macOS Apple Silicon rc.3 验证，Windows 对话入口待补验；其他平台与历史验证范围见[产品说明](../../product/README.md#平台与验证范围)。

## 用户安装

1. 安装受支持的官方 DSH 客户端，打开原生“插件 / Plugins”页面。
2. 在已完成初始化或迁移的 Profile 中，通过原生插件管理器安装 Alcor 的 `.tgz` 包。安装后退出并重新打开 DSH；插件的安装、启用、停用及卸载按重启生效使用。
3. 使用窗口顶部的切换按钮选择 **Alcor** 或 **DeepSeek Harness**。模式切换即时生效，不需要重启，也不会另开浏览器或网页服务。分别保存窗口的模式和上次位置。

安装使用 DSH 的宿主、模型、会话、工作区、插件管理和桌面承载，不修改官方 App 文件。包内的五组界面扩展由原生 Bundle 在当前 Profile 中装配，保留官方模块身份以兼容现有插件；它们是明确标注来源和 MIT 许可的 Alcor 维护衍生模块，不是官方发行包。卸载后重新打开 DSH，恢复原生界面；会话、配置和业务记录保留。

## 使用与数据

Alcor 提供事务、日程、简报、账单与自动化。安装并启用本插件后，普通 DSH 主对话和 Alcor 主对话均可发现业务技能并直接调用 `alcor_business`；用户来源、主会话、宿主访问策略和操作审批检查继续生效。新建对话时选择 **Alcor** 可使用秘书人格。简报执行预设由调度器使用，历史会话沿用原预设。

旧版 Stella 的资料应保存在默认工作区之外的恢复归档中；历史技能和数据库路径不作为当前业务入口。

QQ 社交由独立上游插件负责，插件注册的侧栏页面显示在「系统」分组。秘书不加载社交人格、长期社交记忆或主动交流队列，旧记录由迁移备份保留。

小熊默认出现在 Alcor 业务页面的右下角。悬停可预览输入框，点击可展开并保持打开，按 Esc 可收起。用鼠标拖动小熊，或聚焦后用方向键移动。切页会保留草稿和对话。小熊按工作区续聊，在主聊天中打开的 Alcor 会话优先使用。首次发送时按需创建会话，消息随附当时的页面、已选日期和记录标识。在小熊中可以打开完整对话。进入主聊天后直接使用主聊天输入框。

简报按日期保存。在 **简报 → 简报设置** 可以指定时区，留空时采用系统时区。每次从上次成功采集处继续，最多回溯到前一天零点；同日的新进展会整合到已有条目中。没有新信息时保留正文和版本。定时与手动简报共用已开启的本机和外部来源、有效账号及已保存范围。来源或模型失败后可继续原任务。

历史对话保持可读；旧会话若继续请求 `stella_*` 工具或 `/stella-*` Skill，需改用当前 `alcor_*` 工具或 `/alcor-*` Skill，必要时新建 Alcor 会话。

官方 Desktop 使用自带的 Python 运行环境执行随包领域服务，无需用户另装 Python。Web 开发预览仍需要 Python 3.9+。业务 SQLite 位于当前 Profile 的 `alcor/business/`；旧版位于 `stella/business/`，须经受控离线迁移，与原生 Host 工具和页面共用；旧独立客户端的数据通过显式离线迁移导入，不在安装时自动读取。功能差异以源码仓库 `product/feature-parity.md` 为准，不把安装闭环当作所有原六项功能已经全部迁完。

Apple 日历与提醒事项由可选原生插件 `@alcor/apple-sync` 管理：点击同步纳入全部来源并保留分类／清单；授权由用户操作发起。在 **设置 → Alcor** 中可修改小熊名称、显示小熊、切换悬停展开或恢复小熊的默认位置；学校与邮箱账号由各自插件管理。工具使用宿主当前会话的可用性、访问模式、审批和凭据设施，不再保存额外的 Alcor 逐工具白名单。停用时暂停所属自动化；重新启用不自动恢复已暂停的定时任务。

业务采用已选择的本机可信应用模式，同账号的其他插件和执行工具可能访问本机数据，不承诺系统级隔离。宿主工具限制、凭据撤销复核，以及私人来源的主对话／委托执行检查继续有效。自动化发送用户填写或保存的任务；生成简报会将所选来源内容交给用户配置的模型。打开页面或切换模式不会自动发送私人业务数据。

## 开发与兼容

完整来源与界面扩展摘要见 `vendor/NATIVE-UI-PROVENANCE.json`，许可随衍生模块保留。开发安装、构建、官方 Desktop 验证和已知限制见源码仓库 `product/README.md`、`product/compatibility.md`。官方客户端的 UI 根节点不支持本组合的无重启热替换；不将热安装／热卸载作为已支持能力。

事务默认直接展示全部事务，未完成和已完成分组平铺；重复事务在列表中直接完成本次。Alcor 本地重复事务按其时区投影一个当前待办，编辑和删除仍针对原系列。Apple 导入的重复事务保留来源实际到期日，完成后由 Apple 返回的结果推进；已完成的独立来源记录保留，不按同名自动合并。

日程与事务支持右键或 Shift+F10 打开操作菜单，选择“显示简介”查看标题备注、日期时间、重复提醒和分类／清单等信息，并进入原有编辑或删除确认。日期视图中的点击同样可查看简介，事务列表的详情和子事务入口保留。只读、已完成历史及待 Apple 确认记录按既有能力限制操作；拷贝仅写入用户可见文本。菜单不提供产品没有的邮件发送、剪切粘贴或创建复制项目。

0.1.55：事务页详情与编辑统一为右侧面板，保留左侧列表及筛选状态。子事务树、重复记录、完成/重开、清单、标签和提醒沿用现有功能；支持草稿保护、固定操作区及窄窗口。

0.1.54：日历内日程和事务的详情、编辑与新建统一使用右侧面板。面板独立滚动、底部固定操作；未保存修改提供继续编辑或放弃，保存失败保留草稿。窄窗口显示全宽详情，沿用现有只读、重复和同步规则。

0.1.53：日程页重排日期导航、视图切换与时间网格；日程和事务统一浅灰账户分组侧栏，日历保留多选显示与底部月历，事务保留单清单导航。数据、来源权限与同步规则沿用现有实现。

0.1.52：事务页增加清单侧栏和快速添加，任务行显示备注预览；清单管理统一搜索、颜色、Apple 账户、草稿、分项权限与待确认操作。子事务缺省继承父事务清单，已有数据不迁移。

AgentHub 已拆为独立开发者插件 `@alcor/agent-hub`，仅在 DSH 工作台提供入口；Alcor 不再拥有协作运行时、数据写入、界面或协作 Skill。旧协作数据只读迁移到独立插件，原始数据保留。
