# 简报插件适配

当前结构：DSH 插件持有账号、连接与资源；Alcor 的简报来源适配层负责发现元数据、读取已选来源并转换为简报材料。UI 是「简报 → 设置」中的只读卡片；账号开关和范围位于对应插件，没有独立数据页、数据中心数据库或另一套凭据库。

## 支持范围

- 本机日程、事务、账单继续调用所属业务服务。
- 现有学校 `stellaElearning` 及 `mcp__elearning__fetch`、课程列表继续兼容，已保存账号身份和课程范围不重置。
- 现有邮件 MCP 的 `list_sources` / `fetch_messages` 通过适配器转换，保留邮箱身份和游标契约。
- 新原生 DSH 插件通过下述两个工具提供明确只读契约。不根据工具描述猜测调用参数，不把所有已安装工具都开放给简报。插件未实现契约不会出现在可选列表中。

## 原生插件协议

插件使用宿主的 `ctx.tools.register(defineTool(...))` 注册成对工具，`<prefix>` 为 1–64 个英文字母、数字、下划线或连字符；宿主 SDK 必须使用可选 peer，不能安装自己的 DSH 核心组件。

`<prefix>_briefing_sources` 接收 `{}`，返回元数据对象：

```json
{"sources":[{"id":"inbox","account_id":"stable-account-id","label":"工作资料"}]}
```

目录最多 200 个来源。每个 `id` 为稳定资源范围（例如一个文件夹），1–80 个英文字母、数字、点、下划线、冒号或连字符；`account_id` 随账号变化，最长 200 字符。`label` 为用户可读名称，最长 200 字符。返回目录不得读取正文、改变业务状态或包含凭据。不同范围应使用不同 id。

`<prefix>_briefing_fetch` 接收：

```json
{"source_id":"inbox","account_id":"stable-account-id","since":"2026-11-04T00:00:00Z","until":"2026-11-05T00:00:00Z","offset":0,"limit":100}
```

插件必须核对当前账号及资源访问权，只读所选范围，返回：

```json
{"source_id":"inbox","account_id":"stable-account-id","items":[{"source_id":"document-123","title":"标题","occurred_at":"2026-11-04T12:00:00Z","snippet":"内容摘要","url":"https://example.com/item/123"}],"next_offset":null,"errors":[]}
```

每页最多 100 项。条目 `source_id` 必须在该账号和资源范围内稳定，`occurred_at` 为带时区的 ISO 时间；可选 `thread_id`、`sender`、`payload`、`published_at` 和 `source_updated_at`。请提供原始的发布时间或实际更新时间，截止时间和采集时间分别保存在对应字段。成功提交的窗口为左开右闭；首次采集或跨过回溯下限时包含前一日零点。一个来源返回错误会保留前次检查点，重试复用已完成来源。`next_offset` 为前进的整数偏移，结束必须为 null；错误不得伪装为空来源成功，部分失败在 `errors` 中报告。适配层限制分页次数，拒绝格式错误、账号或资源不一致。工具返回原生对象；MCP 包装使用 `structuredContent.value` 中的同一对象。

Alcor 将来源保存为 `plugin:<prefix>:<id>`、原账号和工具名，并保留所选范围。插件改名或改变稳定 ID 后，需要用户重新选择；不会猜测迁移到其他账号。插件内部秘密、私有对象和业务库不作为适配层依赖。

## 授权与执行

- 打开选择窗仅枚举元数据。新来源默认不选，生成时才读取所选正文并交给当前模型。
- 邮箱与学校实时来源取自启用插件的有效账号，旧邮箱订阅不再控制可用性；课程/本机范围仍由用户插件页面保存，Agent 不得扩大范围或通过课程枚举绕过该边界。对话授权另行管理，后台模板仍仅使用本机来源。
- 每页采集和模型阶段复核已保存授权；撤销后停止后续访问。已发送内容不能撤回。停用插件导致工具不可用时报告来源失败，不把断开状态表示为成功。
- 账号、资源权限和连接的实时状态由插件负责；返回身份再次由适配层校验。DSH 插件是本机可信代码，这份只读契约不能隔离恶意插件。
- 既有源配置保存在原简报 settings 中，不迁移到新库；历史、游标和业务对象继续保留。删除数据页不删除用户数据。

## 验证

`briefing-adapter.test.mjs` 覆盖目录只读调用边界、无关工具不执行、格式／账号／资源校验、分页撤销与断开。`briefing-ui-check.py` 实际安装独立合成 DSH 原生插件，验证只枚举不采集、只读勾选来源、分页进入简报、修订和行动；定时模板不继承外部授权。`source-plugins-check.py` 验证原生插件中的学校凭据、课程选择和移除，`mcp_check.py` 验证继承 DSH 工具策略的对话调用。全部使用合成数据，真实服务需另行验收。
