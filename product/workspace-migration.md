# Stella 工作区与旧版接入

状态：`0.1.0` 开发预览。目录登记和身份快照已实现，不等于旧业务迁移。

## 文件与身份分开保存

DSH 和 Stella 使用同一个工作区目录、列表和原生选择流程。Stella 不再维护个人／项目绑定，也不创建专属文件根；新对话直接交给 DSH 选择当前或最近使用的目录，仅显式指定 `stella` Preset。模式仍分别记住上次页面与会话，恢复已有会话时沿用其原目录。

“设置 → Stella → 工作区与旧版接入”中的单一“DSH 文件工作区”列出宿主已有目录。打开选中项会进入该目录下的空白 Stella 会话；登记已有目录直接写入 DSH 原生目录列表，文件不搬动，原会话和草稿保留。DSH 原生侧栏也可使用同一项。更换目录不复制身份、业务记录或会话库。

Stella 身份快照保存在独立的 `stella_workspace` storage-domain，业务记录继续由各业务 domain 保存。旧开发预览的绑定字段仅保留读取兼容，不参与工作区选择；`bindWorkspace` 开发接口已移除。此前登记的 `dsh-personal` 作为普通 DSH 目录保留，不删除其中可能存在的文件，也不再强制使用。目录登记不授予文件、Shell 或外部工具能力。

## 预览、导入与回退

在“设置 → Stella → 工作区与旧版接入”明确填写旧应用数据、共享资源、用户数据、Agent 状态四个目录。单目录旧布局可让后三项指向同一路径。

预览只读取 Agent 目录的 `AGENT.md`、`RULE.md` 和用户目录的 `USER.md`，以及固定资产的存在状态；不读取凭据、浏览器资料或业务数据库正文。身份文件仅接受最多 64 KB 的普通 UTF-8 文件；固定子路径中的链接、硬链接和特殊文件拒绝读取。预览可展开正文并选择文件。预览及保存不调用模型。

导入前重新读取并比较指纹，来源已变化时要求重新预览。选中内容复制为本机快照，原文件保留原位；保存上一版供一次回退，初次导入也能退回内置身份。重复导入相同内容不丢弃原备份。修订检查阻止旧设置页覆盖新配置。

导入身份仅用于明确用户输入发起的 Stella 主会话，发送给用户选择的模型。普通 DSH 会话、协作子 Agent 和定时任务不加载该快照；旧规则不能授予工具或权限。已经发送到会话历史的内容不会因回退而撤回。该机制属于本机可信应用模式，同账号其他插件和执行工具仍可能访问本机文件。

## 仍待迁移

Skills、MEMORY/记忆库、知识、旧会话、业务数据库和旧定时目前仅显示存在状态。当前六项页面不会自动使用这些旧数据，也不启动旧 Runtime。数据库迁移需要各模块契约、冲突检查、幂等导入、备份恢复与独立验收，见 [原功能对照](feature-parity.md)。

DSH 原生设置在窗口跨越侧栏断点时可能重新挂载；调整窗口大小前先保存表单。
