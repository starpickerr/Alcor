# OBS 下载分块兼容修复

2026-11-15：MCP 1.0.11、@alcor/elearning 0.1.17 修复学校 OBS 返回的课件正文额外包含 AWS 上传分块标记及 CRC32 尾部的问题。此前这些编码字节也被计入文件大小，触发 download_size_mismatch；不是已证实的学校元数据过期。

受控真实样本：原始 PDF 下载为 1,681,501 字节；解析出 103 个分块，CRC32 匹配，正文恰为学校标注的 1,680,641 字节，可解析为 38 页。两份 PPTX 同样在校验恢复后与学校标注精确一致，ZIP CRC 与演示文稿结构检查通过。真实课件、签名下载 URL、账号及凭据不进入仓库。

## 行为与边界

- 沿用 HTTP 接收完整性、512 MB 上限、HTTPS/下载地址、取消、目录安全和不覆盖约束。
- 仅在接收大小不等于有效元数据时检查已复现的分块格式；大小一致的普通文件不转换。
- 仅当分块语法、结束符、唯一 CRC32 尾部、无额外尾随数据、CRC32 值和解码后精确字节数全部通过，才替换内部临时文件并发布正文。
- 普通大小不符仍拒绝保存；编码或校验失败返回 download_integrity_error。无法证明文件损坏或元数据过期时不作该推断，也不建议更改审批策略。
- 解码流式执行，按原始大小限制内存和输出，取消或失败清理临时文件；单文件与配置目录同步共用实现。

## 验证

独立 MCP 全部 160 项 pytest 与 60 项 subtests 通过，含有效解码、坏 CRC、截断、非法长度、缺失尾部、多余数据、普通文件不误转换、取消清理、原有路径与文件保护，以及实际 MCP 传输错误脱敏。新增成功用例先复现 download_size_mismatch，再由实现修复。

真实三文件经相同下载实现从学校签名地址重新获取、校验并保存到用户原课件目录，未覆盖已有文件。浏览器只用于获取当前已登录学校页面中的授权下载跳转；未读取浏览器或 DSH 的密码、Cookie 或认证数据库。

本次仅变更 Mac eLearning 发行包及独立 MCP；未改变秘书和 AgentHub 的公共进程代码。之前插件诊断分支的 Windows 验收仍按原交接独立完成。

格式依据：[AWS S3 trailing checksums](https://docs.aws.amazon.com/AmazonS3/latest/userguide/checking-object-integrity-upload.html)、[RFC 9112 §7.1](https://www.rfc-editor.org/rfc/rfc9112.html#section-7.1)。
