# 官方侧栏激活修复（0.1.113）

## 原因与行为

共享模式原先通过 `loader.update({disabled:true})` 停用官方侧栏客户端模块，再声明同名工作区与设置插槽。rc.3 插件页按服务端仍启用的模块清单等待激活，因此打开内置插件时报 `dsh-client-ui-sidebar is waiting for activation`。首次启动审计后的延迟交接不能修复后续同步。

现在官方侧栏模块、根侧栏及其子插槽始终保留。Alcor 通过品牌和 `sidebar.session.action` 扩展承载原有新对话按钮与应用／系统分组，复用 SecretarySidebar 的导航和 AgentHub 范围逻辑。样式只在 Alcor 扩展存在时保留原侧栏外观；工作区、会话与设置仍由官方组件负责。切回 DSH 或卸载时撤销扩展及对应样式，部分注册失败回滚本次贡献，不触动原生组件。原生面板列表在 Alcor 模式由原系统分组承载，避免重复导航。品牌容器高度与 32px 图标匹配，避免官方 24px 行高裁切图标。

## 验证与范围

- 基于已安装版本对应的 `abb508f` 开独立分支 `fix/sidebar-activation-20261115`；继承尚待 Windows 验收的插件诊断分支，不将这一前置范围隐式发布到 main。
- 45 项初轮检查通过；补充原导航复用和 AgentHub 范围回归后 46 项针对性检查通过。
- 官方 rc.3 SlotCore 实现通过品牌优先级、侧栏／工作区对象保留、模式清理验证。
- 最终根测试 550 项：548 通过，2 项 Windows 跳过。
- 官方 Mac DSH 0.2.2-rc.3 的真实内置插件页已无激活同步错误，Alcor 事务入口可打开；个人数据在安装前冷备份，初轮仅包清单及锁文件改变，其余 293 个文件摘要一致。
- 未修改官方应用、签名、模块、权限策略或凭据。个人截图、包摘要与恢复材料只保存在本机。
