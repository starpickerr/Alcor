# Alcor 通道适配

通道原生插件通过 `ctx.alcorSecretary.channels.register(adapter)` 注册一个账号实例。插件注入 `alcorSecretary`，在自身 effect 中注册，并把返回函数作为 disposer。停用时取消注册，历史、账号归属和投递回执由 Alcor 保存。QQ 适配源码为 `scripts/product/qq-conversation-info.mjs`，从固定原始包构建为独立原生插件。

## 适配接口

| 字段或方法 | 契约 |
| --- | --- |
| `id`、`account`、`label` | 通道 ID、稳定账号 ID、显示名称。同一通道可注册多个账号实例；账号 ID 使用字母、数字、点、下划线或短横线。 |
| `sourceKind` | 该插件实际产生的宿主消息来源类型。 |
| `resolve(sessionId)` | 返回所属会话的 `kind`、`peer`、`label`、`audience`、`owner`。无关会话返回空值。 |
| `actor(route, source)` | 依据平台已认证元数据和当前权限返回记忆访问主体。正文中的身份声明不参与认证。 |
| `messages(route, events)` | 将宿主记录转换为 `seq`、`role`、`text`，可带 `time`、`nickname`、`ambient`。助手角色为 `Alcor`，时间为毫秒时间戳。 |
| `history(route, beforeSeq)` | 可选的只读平台历史，返回 `messages`、`hasMore`、`beforeSeq`。消息 `seq` 用于稳定排序和去重；平台游标与排序序号不同时使用消息的 `cursor`，翻页使用 `beforeSeq`。不支持的会话返回空值，回退宿主记录。 |
| `info(route)` | 返回连接状态及会话资料，沿用 `channelConversation` 的严格公共数据结构。 |
| `canSend(route)` | 同步检查当前账号、平台策略、连接及会话禁言状态。只读适配器可省略发送接口。 |
| `send(route, text, authorize)` | 串行进入实际平台写操作前再次调用 `authorize()`。返回 `sent`、`deferred` 或 `unknown`，已确认送达时可带 `messageId`。 |
| `isOwnerMember(route)` | 没有专属信任策略的通道沿用成员检查。 |
| `trustedForDelivery(route)` | QQ 根据当前账号的联系人和群白名单决定可选目的地，发送前仍复核路由、在线和禁言状态。 |

`resolve` 提供的会话绑定以通道、账号、会话类型和平台对象共同确定。已有 Session 不会自动换绑到另一账号。只有明确绑定主人的私聊可使用 `personal` 范围；新通道的其他范围使用 `channel:<id>:<account>:…`。QQ 的既有 `group:<群号>` 与原会话 ID 保留兼容。

Alcor 统一处理侧栏目录、只读历史、缓存、空间归属及外发授权。平台特有的消息信封、发送者字段和权限检查由适配器负责。工作台会话继续使用 DSH 的人格、工具及原权限。

QQ 群历史读取 NapCat 的平台记录，包含未触发接话的普通消息和真实发送的回复，与 Agent 是否接话分开。打开的历史页每四秒刷新，隐藏时暂停，离线保留已缓存内容。NapCat 的消息 ID 是不透明翻页游标，真实序列号用于排序；向前翻页显式使用 `reverseOrder`。

已允许的群消息在筛选接话前写入本群记忆日志，保留认证成员与消息时间。读取历史时可补齐最近一天的遗漏记录，并按平台消息 ID 去重；较旧记录只供浏览。补齐不会重放 Agent 回合或发送旧消息。被动采集沿用已有日志容量和整理机制，不为每条群消息调用模型。自主接话判断使用模型支持的低推理档位及独立输出额度，直接 @ 的空文本消息也进入正常处理。

## 人格与群聊

侧栏「人格」编辑唯一公开身份。名字、角色描述和可选的对话示例一起参与群聊接话判断与 DSH 实际回复。示例用于表达风格，和真实经历分开保存。已启用群里，直接 @、点名及引用 Alcor 在本群的发言均进入人格判断。真诚求助和随口招呼可以得到不同的回应。多位成员同时点名时可以分别回应或沉默，显式管理指令沿用 QQ 命令处理。普通群消息按发言关系、当前话题及人格决定是否参与；显式配置的仅提及时回应继续生效。重连后从当前群获取最近消息，日常接话可参考最多 120 条、约 2.4 万字符的背景。需要了解更早的事情时，DSH 可以逐页读取本群平台历史，或检索保留的日志、摘要与关系记忆。

主人可以在私人对话里引用已启用群中相关的发言。其它可信联系人有各自的私聊记忆，群内交流沿用本群经历。关闭通道、撤销白名单或更改账号后会重新验证来源。

设计参考：AstrBot 的[角色及示范对话](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/persona_mgr.py)，[Persona Presence](https://github.com/Sihnbaobao/astrbot_plugin_persona_presence) 的群聊参与判断，[LivingMemory](https://lxfight-s-astrbot-plugins.github.io/astrbot_plugin_livingmemory/en/features) 的经历与群记忆，以及 [Private Companion](https://github.com/menglimi/astrbot_plugin_private_companion) 的低频主动联系。Alcor 在 DSH 的会话、模型和调度服务中实现这些行为。

QQ 私聊和群聊都按当前人格、话题和对方意图组织回答。借鉴 Aurabot 的显式停顿标记，模型可以用 `|||` 选择分条。普通段落、列表和代码保留原样，发送仍遵循原有平台限制、队列和逐条授权。中途失败或撤销按结果未知处理，避免整段重发。


## 主动跟进投递

在「人格 → 主动交流」开启跟进并选择送达位置。模型可根据对方说过的原话记下一件值得关心的事，无须对方先要求提醒。跟进提议和依据保存在同一听众范围，话题解决后可在投递前取消。每个可信 QQ 联系人或群可以分别授权，新增授权持续到撤销；已有定期授权按原期到期。同一条私人跟进只送达选定的主人联系人或桌面，其他联系人和群的跟进只使用各自的经历和目的地。

没有待办话题时，DSH 也可在已授权的 QQ 联系人或群中判断是否主动问候。判断使用公开人格、上次实际交谈时间、近期对话和对方表达过的界限，可选择发送、晚些再考虑或在这段沉默中保持安静。新的来信会使尚未发出的问候失效。已发送而对方一直没回应时，下一次判断逐步延后；结果未知的问候不重发。

到期检查复用 DSH Schedule，每分钟检查一次，使用专用内部会话，核对调度来源和实际投递回执后执行。已授权的便笺和外部跟进到期时，通过无工具的模型调用，在原听众范围内核对记忆依据、原问题和期间的新发言。模型可以取消、推迟或改写消息，只能选择已授权的去处。主人私聊和桌面便笺同时开启时可以选择桌面；群跟进只能留在原群。临发送前再核对授权、消息版本和时段。新消息使旧决定失效；模型不可用或输出无效时推迟十五分钟。DSH 关闭期间无法发送，重新运行后继续处理尚未过期的事项。安静时段沿用本机时间的 21:00 至次日 09:00，同一听众的跟进间隔至少四小时；事项到期超过一天后失效。

关闭目的地授权会暂停其待发事项。重新授权同一目的地可接续仍有效的待发事项；已绑定的事项不会自动改投另一账号或群。关闭主动跟进取消待发的主动事项，目的地授权独立保存。没有有效授权时，宿主投递任务暂停。

## 回执与恢复

发送前持久记录 `sending`，收到肯定回执后记录 `sent`。重启时未完成的 `sending` 转为 `unknown`。平台超时或响应不确定时，停止该事项的自动重发，主人可以在原通道核对；其他有效跟进仍可继续。

`deferred` 只用于适配器确定尚未执行外部写操作的情况，例如离线、排队后授权被撤销或频控拒绝。队列等待结束后必须再次检查授权、听众、记忆依据、账号及时间限制。QQ 发送沿用 OneBot 的发送串行队列、主动操作频控和审计。

已完成或结果未知的事项不会自动重发；等待中的事项继续受授权和有效期约束。正常记录在适配器运行时转换并缓存。停用插件后可查看已缓存的历史；尚未缓存的旧记录会提示重新启用适配器解码。原始宿主会话仍保留。投递记录中的内容及回执只在当前个人 Profile 保存，终态回执保留三十天。

QQ 接话先检查私聊或群聊权限，再检查「自动回复」和当前会话的静音状态。管理员可在当前会话用 `/silent` 临时静音，`/active` 解除静音；总开关关闭时仍可运行管理命令。可信 DSH 扩展可监听 `alcor/qq-message`，以 `true` 表示已处理消息，否则返回 `undefined`。扩展只接收已经准入的来信。

私聊文本默认等待 1.4 秒停顿，群聊文本等待 2.2 秒；新文本会重新计时，从第一条起最多等 7 秒。每批只包含同一会话中连续的同一发言人。换人、命令、引用、附件与互动卡片划分边界。群聊上一轮尚未结束时，已收齐的这批会等待回合结束或达到最长等待时间，再交给原有队列。停用或断线清除尚未投递的批次。

群内明确点名、@ 或经网关核实的本群机器人引用，优先进入回复阶段。开启「群聊必须 @」后沿用更严格的触发设置。无人点名时，通道先看近期活跃度、公开人格和本群记忆的话题匹配、是否正在接话、静默时段及发言频率。首次主动插话的抽样以 15% 为基础并按相关度调高；冷却 90 秒，每小时最多六次。已参与的话题允许有限续聊，凌晨 1–8 点抑制主动插话。通过本地筛选后再使用模型判断语义。群聊最终回答恰为 `[沉默]` 时不向 QQ 投递。

### 表情、拍一拍与 QQ 空间

Alcor 可按当前语境列出和发送小熊表情，含「庆祝、疑惑、陪伴、收工」四种。主人私聊还能取用该 QQ 号有备注的收藏；群聊只提供公共小熊图。发送工具绑定本轮真实会话，「拍一拍」绑定本轮发言人。每次写操作都检查当前会话、账号、权限、静音状态和现有写操作限额。网关未确认时不重试。

空间写入走 NapCat 的 `send_qzone_msg`。主人可以在 QQ 私聊里让 Alcor 起草文字，也可以用「发条说说：正文」指定发布内容，或「代写并发布说说：主题」授权 Alcor 围绕主题写并发。默认好友可见；将「（仅自己可见）」放在冒号前即可改为仅自己可见。普通聊天、群聊和引用内容不能授予发布权限。发布成功以网关返回说说 ID 为准。

主人在 QQ 设置的「权限」中开启「自主发说说」后，Alcor 可以根据近一天实际送达的聊天回复和表情决定是否写一条小熊手记。素材只记话题类别或表情动作，账号间隔离。没有素材、模型选择跳过、QQ 离线或自动回复关闭时不会发表。自主说说限好友可见，每 24 小时最多尝试一次，发布结果不明确也不会重发同一批经历。主人在私聊中明确指定的说说仍可单独发表。
