# QQ 社交与秘书业务

Alcor 负责事务、日程、账单、简报、自动化和秘书对话。QQ 社交由独立安装的上游 [AuraBot](https://github.com/aureth-labs/dsh-aurabot-qq) 管理。Alcor 不再构建修改版 OneBot QQ 插件，也不加载社交人格、社交记忆或主动交流服务。

## 安装与界面

通过官方 DSH 原生插件管理器安装上游发布版或已核对的固定上游提交，保留其名称、源码及许可证。升级直接使用上游安装流程。Alcor 不包含 AuraBot 的客户端、Host、数据文件、API 调用或特定插件 ID。

第三方插件在 `sidebar.panellist` 注册的入口显示在 Alcor 侧栏「系统」分组，沿用插件注册的名称和页面，使用统一插件图标。没有侧栏入口的插件继续通过原生插件管理器配置。

QQ 网关、联系人与群准入、人格、聊天模型、语音、表情、记忆和主动联系均在社交插件自身管理。QQ 不继承秘书预设或自动挂载 Alcor 私人业务工具，双方不自动同步记忆。DSH 的插件同进程运行，这种职责划分不构成操作系统隔离。

## 从旧接入切换

1. 核对当前安装版本与原始包引用，停止客户端并冷备份 Profile 配置、会话、业务库、旧人格与社交记忆、通道状态及调度记录。
2. 安装新版秘书和独立社交插件，停用旧 `dsh-onebot-qq` 及其所属主动跟进计划。同一机器人账号仅保留一个回复程序。
3. 将原网关、主人身份和仍允许的联系人/群对应到上游配置；公开人格可作为上游人格卡导入。密钥只在本机受保护配置中转移，不进入源码或报告。
4. QQ 新会话和社交记忆由上游建立。旧会话与记忆保持原件及备份；不批量导入 Alcor 私人经历，不迁移待发队列，不重放旧消息或发布操作。
5. 校验秘书业务、第三方入口和 QQ 登录账号。真实联系人/群和空间不发送测试内容。

首轮使用上游 social 权限处理 QQ，不启用本机 Shell/文件工具或 Alcor 私人业务工具。主动联系与自主发布在上游单独配置，旧投递授权不自动转换为永久授权。

## 数据与回退

秘书业务继续使用原 Profile 的 Alcor 业务库，原账号与凭据保持其原生插件所有权。旧社交记忆及通道记录保留，但不再由秘书加载。小熊继续作为秘书对话入口，使用 DSH 的当前对话历史。

AuraBot 默认数据目录位于 `DSH_HOME/plugins-data/aurabot`，不是 Profile 私有目录。测试必须使用独立 HOME、DSH_HOME 和工作区，或显式指定 `AURABOT_DATA_DIR`；仅改变 Profile 名称不足以隔离数据。

回退先停止新插件和客户端，保存新增数据，再用官方管理器恢复原包与配置。恢复旧社交程序前核对旧调度保持暂停、旧队列不会重放；业务后续变化不可用整份旧库覆盖。固定包和原始备份继续保留。
