# Alcor 通道适配

通道原生插件通过 `ctx.alcorSecretary.channels.register(adapter)` 注册一个账号实例。插件注入 `alcorSecretary`，在自身 effect 中注册，并把返回函数作为 disposer。停用时取消注册，历史、账号归属和投递回执由 Alcor 保存。QQ 适配源码为 `scripts/product/qq-conversation-info.mjs`，从固定原始包构建为独立原生插件。

## 适配接口

| 字段或方法 | 契约 |
| --- | --- |
| `id`、`account`、`label` | 通道 ID、稳定账号 ID、显示名称。同一通道可注册多个账号实例；账号 ID 使用字母、数字、点、下划线或短横线。 |
| `sourceKind` | 该插件实际产生的宿主消息来源类型。 |
| `resolve(sessionId)` | 返回所属会话的 `kind`、`peer`、`label`、`audience`、`owner`。无关会话返回空值。 |
| `actor(route, source)` | 依据平台已认证元数据和当前权限返回记忆访问主体。正文中的身份声明不参与认证。 |
| `messages(route, events)` | 将宿主记录转换为 `seq`、`role`、`text`，可带 `time`、`nickname`、`ambient`。助手角色为 `Alcor`，时间为毫秒时间戳。 |
| `history(route, beforeSeq)` | 可选的只读平台历史，返回 `messages`、`hasMore`、`beforeSeq`。消息 `seq` 用于稳定排序和去重；平台游标与排序序号不同时使用消息的 `cursor`，翻页使用 `beforeSeq`。不支持的会话返回空值，回退宿主记录。 |
| `info(route)` | 返回连接状态及会话资料，沿用 `channelConversation` 的严格公共数据结构。 |
| `canSend(route)` | 同步检查当前账号、平台策略、连接及会话禁言状态。只读适配器可省略发送接口。 |
| `send(route, text, authorize)` | 串行进入实际平台写操作前再次调用 `authorize()`。返回 `sent`、`deferred` 或 `unknown`，已确认送达时可带 `messageId`。 |
| `isOwnerMember(route)` | 新通道群组授权需要确认主人参与该群。QQ 沿用既有参与记录和管理员校验。 |

`resolve` 提供的会话绑定以通道、账号、会话类型和平台对象共同确定。已有 Session 不会自动换绑到另一账号。只有明确绑定主人的私聊可使用 `personal` 范围；新通道的其他范围使用 `channel:<id>:<account>:…`。QQ 的既有 `group:<群号>` 与原会话 ID 保留兼容。

Alcor 统一处理侧栏目录、只读历史、缓存、空间归属及外发授权。平台特有的消息信封、发送者字段和权限检查由适配器负责。工作台会话继续使用 DSH 的人格、工具及原权限。

QQ 群历史读取 NapCat 的平台记录，包含未触发接话的普通消息和真实发送的回复，与 Agent 是否接话分开。打开的历史页每四秒刷新，隐藏时暂停，离线保留已缓存内容。NapCat 的消息 ID 是不透明翻页游标，真实序列号用于排序；向前翻页显式使用 `reverseOrder`。

已允许的群消息在筛选接话前写入本群记忆日志，保留认证成员与消息时间。读取历史时可补齐最近一天的遗漏记录，并按平台消息 ID 去重；较旧记录只供浏览。补齐不会重放 Agent 回合或发送旧消息。被动采集沿用已有日志容量和整理机制，不为每条群消息调用模型。自主接话判断使用模型支持的低推理档位及独立输出额度，直接 @ 的空文本消息也进入正常处理。

## 主动跟进投递

在「设置 → Alcor → 人格与记忆」开启主动跟进后，可在「消息送达」分别设置桌面便笺和外部目的地。外部授权绑定账号及具体联系人或群，有效期为七天，随时可撤销。私人跟进默认选择一位已绑定的主人联系人；群跟进只使用原群记忆并投到原群。桌面 QQ 历史保持只读。

到期检查复用 DSH Schedule，每分钟检查一次，使用专用内部会话，核对调度来源和实际投递回执后执行。已授权的便笺和外部跟进到期时，通过无工具的模型调用，在原听众范围内核对记忆依据、原问题和期间的新发言。模型可以取消、推迟或改写消息，只能选择已授权的去处。主人私聊和桌面便笺同时开启时可以选择桌面；群跟进只能留在原群。临发送前再核对授权、消息版本和时段。新消息使旧决定失效；模型不可用或输出无效时推迟十五分钟。DSH 关闭期间无法发送，重新运行后继续处理尚未过期的事项。安静时段沿用本机时间的 21:00 至次日 09:00，同一听众的跟进间隔至少四小时；事项到期超过一天后失效。

关闭目的地授权会暂停其待发事项。重新授权同一目的地可接续仍有效的待发事项；已绑定的事项不会自动改投另一账号或群。关闭主动跟进取消待发的主动事项，目的地授权独立保存。没有有效授权时，宿主投递任务暂停。

## 回执与恢复

发送前持久记录 `sending`，收到肯定回执后记录 `sent`。重启时未完成的 `sending` 转为 `unknown`。平台超时或响应不确定时，停止该事项的自动重发，主人可以在原通道核对；其他有效跟进仍可继续。

`deferred` 只用于适配器确定尚未执行外部写操作的情况，例如离线、排队后授权被撤销或频控拒绝。队列等待结束后必须再次检查授权、听众、记忆依据、账号及时间限制。QQ 发送沿用 OneBot 的发送串行队列、主动操作频控和审计。

已完成或结果未知的事项不会自动重发；等待中的事项继续受授权和有效期约束。正常记录在适配器运行时转换并缓存。停用插件后可查看已缓存的历史；尚未缓存的旧记录会提示重新启用适配器解码。原始宿主会话仍保留。投递记录中的内容及回执只在当前个人 Profile 保存，终态回执保留三十天。
